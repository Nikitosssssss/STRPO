## 1. АКТУАЛЬНОСТЬ ПРОЕКТА

### 1.1. Цель проекта

Разработать учебное веб-приложение «Интернет-магазин тортов» на языке Python,
максимально задействовав технологии и приёмы из лекций курса: регулярные
выражения (лекция 1), система контроля версий Git (лекции 3–4), автоматизация
тестирования с помощью Selenium WebDriver (лекции 5–6), методологии разработки
(лекция 8). Приложение должно позволять: открыть страницу с каталогом товаров,
выбрать товар, добавить его в корзину и оформить заказ. Внешние интеграции
(платёжные системы, SMS, службы доставки) по условию задания не реализуются.

### 1.2. Актуальность приложения

Малые кондитерские производства и домашние кондитеры всё чаще продают свою
продукцию через интернет: покупателю неудобно звонить и согласовывать заказ по
телефону, а продавцу — принимать заказы в переписке в мессенджерах. Проблему
решает простой интернет-витрина-магазин: покупатель сам выбирает торт из
каталога, указывает количество, дату и способ получения, а кондитер получает
оформленный заказ с контактными данными. Данное приложение — учебная модель
такого сервиса.

### 1.3. Технологический стек

| Слой | Технология | Обоснование |

## 2. ТРЕБОВАНИЯ К ПРИЛОЖЕНИЮ И ПОСТАНОВКА ЗАДАЧИ

### 2.1. Характеристики пользователя

Покупатель — человек любого возраста, выбирающий торт к празднику. Умеет
пользоваться браузером: открыть сайт, найти товар в каталоге, заполнить форму
заказа. Регистрация не требуется — достаточно контактных данных в форме заказа.
Второй пользователь — кондитер (администратор), который просматривает
оформленные заказы; в учебной версии работа с заказами ограничивается их
сохранением в базу данных.

### 2.2. Функциональные требования

1. **Каталог.** Главная страница со списком популярных тортов; страница каталога
   со всеми товарами, поиском по названию/описанию и фильтром по категории.
2. **Карточка товара.** Страница товара с описанием, ценой и формой добавления
   в корзину с выбором количества (1–99).
3. **Корзина.** Добавление, изменение количества, удаление отдельного товара,
   полная очистка корзины (с модальным подтверждением), пересчёт итоговой
   суммы; корзина хранится в сессии пользователя.
4. **Заказ.** Форма оформления: ФИО, телефон, e-mail, адрес, дата доставки,
   интервал доставки, способ получения (доставка курьером / самовывоз),
   комментарий, согласие на обработку данных. Все поля проверяются на сервере.
5. **Подтверждение.** После успешного оформления — страница с номером заказа,
   составом и суммой; заказ сохраняется в базу данных.
6. **Обратная связь.** Сообщения об успехе и ошибках (flash-сообщения).

### 2.3. Нефункциональные требования

- Приложение запускается одной командой `python app.py`, база данных создаётся
  и наполняется демонстрационными данными автоматически.
- Время отклика страниц на локальной машине — доли секунды.
- Валидация формы выполняется на сервере регулярными выражениями; некорректные
  данные не попадают в базу.
- Интерфейс адаптивный (CSS Grid/Flex), русский язык, без внешних CDN и шрифтов
  (работает офлайн).
- Код покрыт автотестами: юнит-тесты валидации и сценарные Selenium-тесты
  полного пути покупателя.
- Разработка ведётся в Git с атомарными коммитами и ветками.

### 2.4. Анализ проблемы и постановка задачи

Проблема: покупателю кондитерских изделий нужен простой способ выбрать торт,
посчитать стоимость и оставить заказ, а учебный курс требует применить набор
конкретных технологий. Задача: спроектировать компактное MVC-подобное
приложение (маршруты Flask — контроллеры, Jinja2-шаблоны — представление,
модуль `database.py` — модель), покрыть ключевой сценарий автотестами и
задокументировать применение каждой лекционной технологии.

## 3. ПРОЕКТИРОВАНИЕ И РАЗРАБОТКА ПРИЛОЖЕНИЯ

### 3.1. Описание источников и структуры данных

Данные хранятся в SQLite-файле `cake_shop.db` (создаётся при первом запуске).
Три таблицы (DDL — в `database.py`, функция `init_db`):

```sql
-- товары каталога
CREATE TABLE products (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    name        TEXT    NOT NULL,   -- название торта
    category    TEXT    NOT NULL,   -- категория: Классика, Муссовые, ...
    description TEXT    NOT NULL,   -- описание для карточки товара
    price       INTEGER NOT NULL,   -- цена, руб.
    weight      TEXT    NOT NULL,   -- вес, например "1,5 кг"
    emoji       TEXT    NOT NULL    -- визуализация вместо фото
);

-- заказы
CREATE TABLE orders (
    id             INTEGER PRIMARY KEY AUTOINCREMENT,
    customer_name  TEXT NOT NULL,   -- ФИО (проверяется регулярным выражением)
    phone          TEXT NOT NULL,   -- +7(999)123-45-67
    email          TEXT NOT NULL,
    address        TEXT NOT NULL,
    delivery_date  TEXT NOT NULL,   -- ДД.ММ.ГГГГ
    delivery_slot  TEXT NOT NULL,   -- интервал доставки
    delivery_type  TEXT NOT NULL,   -- 'delivery' | 'pickup'
    comment        TEXT,
    delivery_cost  INTEGER NOT NULL,  -- 300 руб. доставка / 0 самовывоз
    items_total    INTEGER NOT NULL,
    total          INTEGER NOT NULL,
    created_at     TEXT NOT NULL DEFAULT (datetime('now', 'localtime'))
);

-- позиции заказа (снимок названия и цены на момент покупки)
CREATE TABLE order_items (
    id           INTEGER PRIMARY KEY AUTOINCREMENT,
    order_id     INTEGER NOT NULL REFERENCES orders(id),
    product_id   INTEGER NOT NULL REFERENCES products(id),
    product_name TEXT    NOT NULL,
    quantity     INTEGER NOT NULL,
    price        INTEGER NOT NULL
);
```

Источник каталога — демонстрационные данные (9 тортов в 5 категориях),
добавляемые функцией `init_db` только в пустую базу. Корзина не хранится в БД —
это словарь `{id_товара: количество}` в серверной сессии Flask (кука
сессии подписана `secret_key`).

### 3.2. Разработка приложения

Разработка велась итерационно (лекция 8: итерационная модель), каждая итерация
завершалась коммитом в Git. Порядок работ:

1. **Каркас проекта.** Создана структура папок, `requirements.txt`,
   виртуальное окружение `.venv`, установлены Flask, selenium, pytest.
   Коммит `c0201be`.
2. **Слой данных.** Модуль `database.py`: схема БД, автоматическая инициализация
   и наполнение, параметризованные запросы каталога (поиск `LIKE` с
   экранированием, фильтр по категории), сохранение заказа транзакцией.
   Коммит `419d8e1`.
3. **Валидация.** Модуль `validation.py`: регулярные выражения для всех полей
   формы заказа + функция комплексной проверки `validate_checkout`
   (подробно — раздел 4.1). Коммит `c4c3166`.
4. **Веб-приложение.** Модуль `app.py`: маршруты Flask, корзина в сессии,
   flash-сообщения, context processor со счётчиком корзины. Коммит `58feb78`.
5. **Интерфейс.** Шаблоны Jinja2 с наследованием от `base.html`, стили
   `static/css/style.css`, клиентский скрипт пересчёта суммы в корзине.
   Коммит `c412846`.
6. **Автотесты.** В отдельной ветке `feature/autotests`: сначала юнит-тесты
   валидации (коммит `8711d71`), затем Selenium-тесты с Page Object Model
   (коммит `77637f7`); ветка влита в `main` merge-коммитом `65ef0de`.
7. **Документирование.** Настоящий отчёт (финальный коммит).

Ключевые решения:

- **Корзина в сессии** (`app.py`): серверная сессия Flask не требует БД и
  регистрации; `session.modified = True` гарантирует сохранение изменений
  словаря.

```python
def get_cart():
    """Корзина -- словарь {product_id (str): количество} в сессии Flask."""
    return session.get("cart", {})

@app.post("/cart/add/<int:product_id>")
def cart_add(product_id):
    cart = get_cart()
    key = str(product_id)
    cart[key] = min(cart.get(key, 0) + int(quantity_raw), 99)
    session["cart"] = cart
    session.modified = True
    ...
```

- **Снимок цены в заказе** (`database.py`, `create_order`): название и цена
  копируются в `order_items`, чтобы история заказов не «ломалась» при изменении
  каталога в будущем.
- **Стоимость доставки**: 300 ₽ для курьера, 0 ₽ для самовывоза; итоговая сумма
  считается на сервере.

## 4. ПРИМЕНЕНИЕ ЛЕКЦИОННЫХ ПРИЁМОВ И ТЕХНОЛОГИЙ

### 4.1. Лекция 1: регулярные выражения — модуль `validation.py`

Все проверки формы заказа построены на модуле `re`. Использованы приёмы:
символьные классы и метасимволы, квантификаторы, группировки (в т.ч.
именованные), «просмотр вперёд», функции `re.fullmatch`, `re.sub`.

**Телефон — квантификаторы `\d{3}`, экранированные скобки:**

```python
# Телефон в «человекочитаемом» формате: +7(999)123-45-67
PHONE_RE = re.compile(r"^\+7\(\d{3}\)\d{3}-\d{2}-\d{2}$")
```

**«Мягкий» разбор телефона — именованные группы `(?P<...>)` и нормализация**
(принимает `8 999 123 45 67`, `+7-999-123-45-67`, `+7(999)1234567` и приводит
к единому виду):

```python
PHONE_LOOSE_RE = re.compile(
    r"^\+?(?P<country>[78])\D*(?P<code>\d{3})\D*(?P<a>\d{3})\D*(?P<b>\d{2})\D*(?P<c>\d{2})$"
)

def normalize_phone(raw):
    m = PHONE_LOOSE_RE.match(raw.strip())
    if not m:
        return None
    parts = m.groupdict()          # извлечение частей строки группами
    return "+7({code}){a}-{b}-{c}".format(**parts)
```

**Имя — несохраняющие группы `(?:...)` и квантификатор повторов `+`:**

```python
NAME_RE = re.compile(
    r"^[А-ЯЁA-Z][а-яёa-z]+(?:-[А-ЯЁA-Z][а-яёa-z]+)?"
    r"(?:\s+[А-ЯЁA-Z][а-яёa-z]+(?:-[А-ЯЁA-Z][а-яёa-z]+)?)+$"
)
```

**E-mail — символьный класс с перечислением, `{2,}` для домена:**

```python
EMAIL_RE = re.compile(r"^[A-Za-z0-9._%+\-]+@[A-Za-z0-9.\-]+\.[A-Za-z]{2,}$")
```

**Дата — именованные группы `day/month/year`:**

```python
DATE_RE = re.compile(r"^(?P<day>\d{2})\.(?P<month>\d{2})\.(?P<year>\d{4})$")
```

**Количество — негативный «просмотр вперёд» (lookahead) `(?!0)`:**

```python
# Запрещает ведущий ноль: 01 и 0 не пройдут, 1..99 — пройдут.
QUANTITY_RE = re.compile(r"^(?!0)\d{1,2}$")
```

**Замена — `re.sub`** (сжатие двойных пробелов в имени перед сохранением):

```python
name = re.sub(r"\s+", " ", name)
```

Все регулярные выражения компилируются один раз на уровне модуля
(`re.compile`) — готовые объекты используются в каждом запросе. Дата после
проверки формата дополнительно проверяется календарно (`datetime.strptime`),
потому что `31.02.2026` формально соответствует шаблону, но такой даты не
существует — регулярные выражения не умеют сравнивать числа.

### 4.3. Лекция 5: Selenium WebDriver — запуск браузера и поиск элементов

**Виртуальное окружение (приём из лекции 5):** для проекта создано изолированное
окружение и установлены зависимости:

```
python -m venv .venv
.venv\Scripts\activate
pip install flask selenium pytest
```

**Запуск браузера** (`tests/selenium_tests/test_order_flow.py`). В лекции
показана ручная установка ChromeDriver и добавление в PATH; в современных
версиях Selenium (4.6+) работает Selenium Manager — драйвер подбирается и
скачивается автоматически. На машине разработки установлен браузер Edge
(движок Chromium, полный аналог Chrome для WebDriver), поэтому тесты запускают
Edge в headless-режиме:

```python
options = webdriver.EdgeOptions()
options.add_argument("--headless=new")
options.add_argument("--window-size=1280,900")
cls.driver = webdriver.Edge(options=options)
cls.driver.implicitly_wait(5)   # неявное ожидание -- приём из лекции 5
```

**Поиск элементов** — все способы из лекции: `find_element(By.ID)`,
`By.NAME`, `By.CSS_SELECTOR`, `By.XPATH`; отправка данных `send_keys`,
нажатие `click` — инкапсулированы в базовом классе страниц:

```python
class BasePage:
    def find(self, locator):                      # locator = (By.ID, "search-input")
        return self.driver.find_element(*locator)

    def click(self, locator):
        self.wait_visible(locator)
        self.find(locator).click()

    def type_into(self, locator, text):           # очистка + send_keys
        field = self.wait_visible(locator)
        field.clear()
        field.send_keys(text)
```

Пример XPath-поиска по тексту элемента (каталог → страница товара):

```python
link = (By.XPATH, f"//span[@class='product-name' and text()='{name}']")
```

**Ожидания:** неявное (`implicitly_wait(5)`) задано глобально; для элементов,
появляющихся после переходов, применяется явное ожидание —
`WebDriverWait` + `expected_conditions` (лекция 6):

```python
def wait_visible(self, locator):
    return self.wait.until(EC.visibility_of_element_located(locator))
```

### 4.4. Лекция 6: формы, get_attribute, execute_script, модальные окна

**Работа с элементами форм.** В форме заказа используются radio (способ
получения), checkbox (согласие), раскрывающийся список (интервал доставки) —
все три типа из лекции. Примеры из тестов:

```python
# radiobutton: клик и проверка выбора
checkout.choose_pickup()
self.assertTrue(checkout.find(CheckoutPage.RADIO_PICKUP).is_selected())

# checkbox: is_selected до/после клика
self.assertFalse(checkout.agree_is_selected())

# раскрывающийся список: класс Select
Select(self.find(self.SLOT)).select_by_value("14:00-18:00")
```

**Метод get_attribute** — чтение атрибута `value` числового поля:

```python
def quantity_value(self):
    return self.attribute_of(self.QTY_INPUT, "value")   # get_attribute
```

**Метод execute_script** — вызов клиентской функции пересчёта суммы строки
корзины (JavaScript объявлен в `templates/cart.html`):

```python
row = cart.first_row()
self.driver.execute_script(
    "var row = arguments[0];"
    "var input = row.querySelector('.qty-input');"
    "input.value = '3';"
    "recalcRow(row);",     # функция, объявленная на странице
    row,
)
self.assertEqual(cart.first_row_sum(), "7200 ₽")
```

**Модальные окна.** Кнопка «Очистить корзину» вызывает нативный
`confirm()` (`onsubmit="return confirm('Очистить корзину полностью?');"`).
Тест читает текст диалога и принимает либо отклоняет его через
`driver.switch_to.alert` — приём из лекции 6:

```python
def clear_with_confirm(self, accept=True):
    self.click(self.CLEAR_BTN)
    alert = self.driver.switch_to.alert
    text = alert.text
    if accept:
        alert.accept()      # «ОК» -- корзина очищается
    else:
        alert.dismiss()     # «Отмена» -- товары остаются
    return text
```

### 4.5. Лекция 6: unittest и pytest

Юнит-тесты валидации написаны в стиле unittest (классы `unittest.TestCase`,
методы `assert*`, `subTest`) — как в лекции, — но запускаются также pytest'ом,
что демонстрирует их обратную совместимость. Именованные классы по темам:
`TestNameValidation`, `TestPhoneValidation`, `TestEmailValidation`,
`TestDateValidation`, `TestQuantityValidation`, `TestValidateCheckout`.

```python
class TestPhoneValidation(unittest.TestCase):

    def test_normalize_loose_formats(self):
        self.assertEqual(normalize_phone("8 999 123 45 67"), "+7(999)123-45-67")

    def test_valid_phone(self):
        self.assertTrue(is_valid_phone("+7(999)123-45-67"))
```

Selenium-тесты организованы классами фикстур unittest: сервер приложения и
браузер создаются один раз в `setUpClass` (экономия времени), между тестами
сессия браузера очищается (`delete_all_cookies` — у каждого теста свежая
корзина):

```python
@classmethod
def setUpClass(cls):
    BasePage.BASE_URL = BASE_URL
    start_app_server()                    # Flask в фоновом потоке
    cls.driver = webdriver.Edge(options=options)
    cls.driver.implicitly_wait(5)

def setUp(self):
    self.driver.delete_all_cookies()      # каждый тест с пустой корзиной
```

Запуск и результат:

```
.venv\Scripts\activate
pytest tests\test_validation.py -v
python -m unittest discover -s tests\selenium_tests -v
```

### 4.6. Лекция 6: паттерн Page Object Model

Каждой странице соответствует класс в `tests/selenium_tests/pages/`:
`BasePage` (базовые операции), `CatalogPage`, `ProductPage`, `CartPage`,
`CheckoutPage`. Локаторы собраны атрибутами класса — при изменении вёрстки
правится только страница-объект, тесты не меняются. Сами тесты формулируются
терминами предметной области, без обращения к драйверу:

```python
def test_full_order_flow(self):
    cart = CatalogPage(self.driver).open() \
        .open_product_by_name("Наполеон классический") \
        .set_quantity(1) \
        .add_to_cart()
    checkout = cart.go_to_checkout()
    checkout.fill_valid_form().submit()
    self.assertIn("оформлен", checkout.success_title())
```
